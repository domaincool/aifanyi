aifanyi.com 管理后台实施方案

Admin Console Plan v1.0 · 2026-08-15 · 基于审计报告（audit-report-20260815.html）P1 缺口制定
4 个阶段 5 个新页面 ~10 个新 API 预计 5-7 天

一、背景与目标

现状痛点：内容（梗词条/盲测题/定价）入库全靠 seed 脚本 + git + 部署，运营每批内容都要走开发流程；运营数据（/api/stats）公开无认证；用户视图只有额度，没有注册来源/活跃度。

方案目标：让运营脱离开发流程独立运转——在后台直接建/改/删词条与盲测题（保存即生效，sitemap 自动收录）；管理员统一查看统计、用户、额度；全部管理操作留痕可审计。

二、现状盘点（已验证）

已有缺口
/admin/credits 额度管理页（查询/调整/对账）无统计看板；/api/stats 公开无认证
requireAdmin 鉴权（ADMIN_EMAILS 白名单）无内容管理（词条/盲测题只能 seed）
4 个 admin API（adjust/reconcile/users/users[id]）用户视图缺注册来源/活跃度
crontab 对账/清理自动任务无管理操作审计日志

三、方案总览（架构）

/admin/layout.tsx（服务端 requireAdmin 守卫 + 侧边导航） ├── /admin 统计看板 Dashboard（成本/调用/用户/内容） ├── /admin/memes 词条管理（CRUD + 批量导入 + 上下架） ├── /admin/blindtests 盲测题管理（CRUD） ├── /admin/users 用户管理（增强列表 + 活跃度） ├── /admin/credits 额度管理（现有，保留） └── /admin/audit 审计日志（管理操作留痕） API 层（全部 requireAdmin + rate-limit + 审计） /api/admin/stats （迁移自 /api/stats，加鉴权） /api/admin/memes GET/POST + /[id] PATCH/DELETE /api/admin/memes/import POST（批量导入 JSON） /api/admin/blindtests GET/POST + /[id] PATCH/DELETE /api/admin/users GET（增强） /api/admin/audit GET（审计日志）

四、页面与 API 设计

1. 统计看板 /admin（Phase A）

卡片数据来源说明
核心指标/api/admin/stats用户数/活跃会话/翻译任务/盲测投票/额度账户/词条数
成本面板TranslationJob + CreditLedger 聚合近 7 天/30 天成本、按模型分布、预算消耗进度
调用趋势TranslationJob 按日聚合折线图（内联 SVG，无外部依赖）
内容概况MemeEntry/Blindtest 计数总数 + 分类分布 + 上下架状态
⚠️ 兼容性：现 /api/stats 被运营每周快照 GET 使用。迁移方案——保留公开精简版（无成本/调用量敏感字段，仅盲测投票数等展示型数据），完整版收进 /api/admin/stats。

2. 词条管理 /admin/memes（Phase B）

能力说明
列表 + 搜索按 term/slug/分类/tag 过滤，分页 48/页（复用 /meme 页聚合逻辑）
新建/编辑全字段表单（term/slug/含义/译文/例句/tags/popularity/分类），slug 唯一校验（term + 两种 slug 风格查重，沿用 batch-005 经验）
上下架MemeEntry 新增 status 字段（draft/published/archived），下架不进 sitemap/首页
批量导入粘贴 JSON 数组（MemeSeed 格式）→ 服务端查重 → 预览冲突 → 确认入库（替代 meme-batch-XXX.ts 流程）
删除软删除（archived）为主，硬删除仅限 draft

3. 盲测题管理 /admin/blindtests（Phase C）

能力说明
列表 + 状态题目、场景、三模型译文状态（已生成/待生成）
新建/编辑sourceText + 场景 + 可选预置译文；保存时后端调用三模型生成匿名译文（复用 seed-blindtests 逻辑，异步任务）
上下架下架题不参与盲测随机

4. 用户管理 /admin/users + 审计 /admin/audit（Phase C/D）

能力说明
用户列表增强现有 /api/admin/credits/users 扩展：注册时间/最近活跃（Session.updatedAt）/翻译任务数/余额
审计日志新表 AdminLog（adminEmail/action/targetId/params/ip/createdAt），所有管理写操作落库

五、数据模型改动

表改动影响
MemeEntry+ status String @default("published") + updatedAt DateTime @updatedAtdb push 增量，300 行数据安全；sitemap/首页查询加 status 过滤
Blindtest+ status String @default("published")盲测随机查询加过滤
AdminLog（新表）id/adminEmail/action/targetId/params Json?/ip/createdAt新建，无迁移风险

六、安全设计

项方案
页面守卫/admin/layout.tsx 服务端 requireAdmin，非 admin 返回 404（避免暴露后台存在）
API 守卫每个 admin route 顶部 requireAdmin + 复用现有 admin-auth.ts
限流管理写操作按邮箱维度限流（复用 rate-limit.ts 滑动窗口）
审计写操作全部写 AdminLog；读操作不记（防日志膨胀）
CSRF会话 Cookie SameSite=Lax（需确认现有配置）+ 敏感操作校验 Origin
内容校验词条 slug 唯一 + term 查重（两种 slug 风格）+ 字段长度上限；导入 JSON 行级校验，坏行跳过不整批失败

八、验收标准

#验收项标准
1运营建词条后台新建 → 词条页/sitemap 实时可见，无需 git/seed/部署
2批量导入含重复 term/slug 的 50 条 JSON → 冲突全部检出，不坏行，入库数与预期一致
3权限非 admin 访问 /admin 与 admin API 全 404/403；未登录全 401
4stats 收敛公开精简版无成本/调用量字段；完整版仅 admin 可见
5审计所有管理写操作在 AdminLog 留痕（含 ip/params）
6回归首页/词条页/盲测/盲测投票/信用系统 E2E 全绿
