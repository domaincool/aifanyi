管理后台 Phase B 详细设计：词条直录通道（Primary）

Admin Console Phase B Design v1.0 · 2026-08-15 · 依据用户拍板决策（并行通道，Primary=后台直录 / Fallback=handoff）
1 个主录入端点 Bearer Ops Token batchId 幂等 自动回退 handoff

一、决策回顾（已拍板）

#决策
1后台直录 = 运营 Agent 的 Primary 通道
2handoff 保留 = Fallback / 异常兜底 / 人工审核通道
3正常情况运营 Agent 优先直接写入后台，不再依赖 handoff 完成日常投递
4后台录入失败/接口异常/校验失败/需人工确认 → 自动回退 handoff
5双通道必须避免重复录入 → 后台具备幂等/去重机制
6handoff 不是平级第二套数据源，最终以后台数据为准
7交接文档明确新流程：Primary=后台直录，Fallback=handoff
8批量导入交互按「后台直录」为主设计，不为兼容 handoff 增加复杂 UI

长期目标：后台稳定后逐步降低 handoff 使用频率，最终让它只作为安全保险存在。

二、架构总览（双通道数据流）

运营 Agent（agent-p6qd） │ ├─ [Primary] POST /api/admin/memes/import ←── Bearer OPS_API_TOKEN │ │ 校验 → 查重 → 事务 upsert → AdminLog → 结构化结果 │ ▼ │ 后台数据（MemeEntry 表，唯一事实源） │ ▼ │ sitemap / 首页热梗 / 词条页 / 盲测 （实时可见，无需部署） │ └─ [Fallback] 检测失败（5xx/超时/校验不过/冲突过多/需人工） │ 写 handoff/meme-batch-XXX-日期.md（带处理状态节）+ 会话短通知 ▼ 工程师读取 → 提取数据 → 调【同一个】/api/admin/memes/import ▼ 入库结果写回 handoff 状态节 + 会话确认（同一查重逻辑，不重复）

三、Agent → Backend 录入接口

3.1 认证：Ops Token（Bearer）

运营 Agent 是机器调用方，不走浏览器 OTP 登录。方案：Ops API Token。

  • 服务器 .env 新增 OPS_API_TOKEN（随机 64 位 hex，不入 git，可轮换）；运营 Agent 侧通过会话安全交接（或写入其受保护的配置）
  • 新统一入口 src/lib/admin/ops-auth.ts → requireOpsOrAdmin()：
  • Authorization: Bearer <token> == OPS_API_TOKEN → ops（运营 Agent）
  • 或浏览器 session 命中 ADMIN_EMAILS → admin（人工管理员）
  • 两者同一权限面，同一审计通道（operator 区分 ops-token / 邮箱）

方法路径用途权限

3.3 批量导入请求 / 响应规范

POST /api/admin/memes/import
Authorization: Bearer <OPS_API_TOKEN>
Content-Type: application/json

{
  "batchId": "meme-batch-008-20260815",   // 幂等键，运营侧生成，UUID 或批次名
  "dryRun": true,                          // true=只预览冲突，不写库
  "updateExisting": false,                 // term 已存在时：false=跳过（默认），true=更新
  "items": [
    {
      "term": "绝绝子",
      "slug": "jue-jue-zi",
      "meaning": "形容好到极致",
      "translation": "Absolutely amazing / Top-notch",
      "example": "这家店的服务绝绝子！",
      "tags": ["流行", "感叹"],
      "popularity": 95,
      "category": "流行语"
    }
  ]
}

// 200 响应（dryRun=false）
{
  "ok": true,
  "batchId": "meme-batch-008-20260815",
  "imported": 45,          // 新入库
  "updated": 0,            // updateExisting=true 时更新数
  "skipped": 3,            // 重复跳过
  "conflicts": [           // 需人工看的行
    { "index": 4, "term": "绝绝子", "reason": "term_exists" },
    { "index": 7, "term": "月光族", "reason": "slug_conflict(yueguangzu)" }
  ],
  "created": ["jue-jue-zi", "..."]
}

// 同 batchId 重复提交（幂等）→ 200，返回与首次相同的 imported/skipped/conflicts，不重复入库

四、批量导入流程（时序）

Step 1 · 运营准备数据
整理 JSON 数组（MemeSeed 格式，与现有 meme-batch-XXX.ts 同构，运营已熟悉字段）
Step 2 · dryRun 预览
调 import 带 dryRun:true → 返回冲突清单（term 重复 / slug 双风格冲突 / 字段缺失）
Step 3 · 修正 / 确认
运营修掉可自动修的冲突（改 slug / 去重），无法判定的留给人工
Step 4 · 正式导入
dryRun:false → 服务端事务 upsert + AdminLog + 结构化结果
Step 5 · 确认完成
运营读 imported/skipped/conflicts → 会话回执「收到，已导入 N 条」；线上 sitemap/词条页实时可见

五、幂等 / 去重策略

层级机制说明
请求级batchId 幂等AdminLog 记 batchId + result 摘要；同 batchId 重复请求直接返回首次结果（不重跑、不重复入库）
行级 · termterm 唯一约束已存在 → skipped（或 updateExisting 更新）；不做双风格 term 归一（term 本身就是原始写法）
行级 · slugslug 唯一 + 双风格查重slug 冲突分两种：精确重复；无连字符风格（yueguangzu vs yue-guang-zu）→ 沿用 batch-003/005 经验，两种风格都查
批内去重同批重复 term首条生效，其余进 conflicts（reason: duplicate_in_batch）
双通道防重handoff 也走同一 import工程师读 handoff 提取数据后【不直接写 DB】，调同一个 import 接口 → 两个通道共享同一查重/幂等逻辑
⚠️ 数据唯一性设计：term 与 slug 都是唯一索引（现有约束保留）；新增 MemeEntry.status（draft/published/archived），下架不影响唯一约束。

六、失败回退 handoff 机制

6.1 触发条件（运营 Agent 侧自动检测）

条件处理
5xx / 网络超时自动重试 3 次（指数退避），仍失败 → 回退
401/403（token 失效）停止调用，会话通知工程师换 token → 回退 handoff 保数据不丢
校验失败且无法自动修正（如字段缺失/格式错误）→ 回退 + 附错误明细
冲突率 > 20%可能数据版本错乱 → 回退 + 人工核对
运营判断需人工确认（如疑似历史数据被误改）→ 回退标注「人工审核」

6.2 回退流程

1. 运营检测失败 → 写 handoff/meme-batch-<序号>-<日期>.md（数据 + 状态节） 2. 状态节：## 处理状态: PENDING（原因: xxx） 3. 会话短通知（按现协议） 4. 工程师读取 → 提取数据 → 调 POST /api/admin/memes/import（同一查重逻辑） 5. 结果写回文件状态节：## 处理状态: IMPORTED（imported N / skipped M / conflicts: ...） 6. 会话回执 → 运营归档
⚠️ handoff 文件从此带处理状态节，是「搬运通道」不是「数据源」——数据永远经 import 接口落库，避免双通道分叉。

七、权限与审计日志

项设计
身份分层人工管理员（session + ADMIN_EMAILS，现有）｜运营 Agent（Bearer OPS_API_TOKEN）｜两者均过 requireOpsOrAdmin()
权限差异DELETE 硬删除仅人工 admin；ops 只能 增/改/批量导入/上下架
审计AdminLog 表：operator（邮箱 或 ops-token）/ action（memes.import / memes.create / memes.update / memes.delete）/ targetId / batchId / params(Json) / ip / createdAt；写操作全记录
限流导入接口按 token 维度（滑动窗口，10 分钟 20 次），防误触发批量重放
Token 管理OPS_API_TOKEN 存服务器 .env（不入 git）；轮换 = 两端同步改；泄露应急 = 立即轮换 + 审计日志排查
