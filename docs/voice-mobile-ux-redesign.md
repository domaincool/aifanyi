> 范围：不破坏语音后端（/api/voice/*）、认证体系（session/登录）、Credit System（统一 Credit Engine 结算）

## 1. 当前 /voice 桌面端 UX 分析（基于现有代码）

**现有结构**（`src/components/VoicePageClient.tsx`，V3 + 移动端极简优化后）：

| 模块 | 现状 | 评价 |
|---|---|---|
| 布局 | 上下双面板：A 说话（zh→en）/ B 说话（en→zh），各带语言下拉 + 录音按钮 | ✅ 面对面语义清晰，桌面可用 |
| 录音方式 | 按住说话（pointer 双保险 + 250ms 误触守卫）/ 自动断句（VAD 600/1200/2000ms）二选一，**默认按住** | ⚠️ 自动断句存在但非默认；按住对手机不友好 |
| Recording 反馈 | 红点 + 秒数计时 | ❌ 无实时音量/波形，反馈弱 |
| Processing | 单一 `translating` 状态（「识别并翻译中…」） | ❌ 无法区分 STT/翻译/TTS 三段 |
| 结果呈现 | 对话气泡（A 左/B 右），含原文/译文/时间/🔊播放 | ⚠️ 气泡有了，但**无暂停/重播/复制** |
| 自动播放 | play() 失败静默降级（playingId 置 null） | ❌ 无显式「点击播放」fallback |
| 额度 | **页面无任何额度展示** | ❌ 用户不知道预计/本次消耗 |
| 语言 | 每次手动选，无记忆 | ❌ 无「最近使用」 |
| 清空 | 无 | ❌ 长对话无法一键清空 |
| 异常 | 权限拒绝/无设备/网络中断中文提示、切后台取消录音、250ms 误触守卫 | ⚠️ 有基础，未覆盖永久拒绝/来电/锁屏/自动播放被拦等 |

**桌面端强项**：面对面双栏语义、VAD 可配置、pointer 事件双保险（松手必达）、误触守卫、极简头部。
**桌面端待补**：波形、三段处理状态、播放控制、额度、最近语言、清空。

## 2. 当前移动端 UX 问题清单

1. **默认按住说话**：手机用户被要求长按录音——不符合「点击即用」直觉，单手操作困难
2. **录音按钮在页面中部**（面板内），非拇指热区，单手够不到
3. **无实时音量/波形**：录音时只有秒数，用户不确定麦克风是否在工作
4. **Processing 黑盒**：一句话翻译可能 5-10s，用户不知道卡在哪一段
5. **结果无复制/重播/暂停**：想再听一遍只能干瞪眼
6. **自动播放被拦时无提示**：iOS 常见，用户以为坏了
7. **无额度提示**：语音是付费功能，用户不知道花多少
8. **语言选择两个下拉并排**（面板内），窄屏易误触、无最近记忆
9. **长对话无法清空**
10. **方向切换不便**：A/B 各管各的，面对面时还要找到对方的按钮
11. **权限异常覆盖不全**：永久拒绝（iOS 需去设置）、来电/锁屏中断无专门提示
12. **触控目标**：部分辅助按钮（取消/播放）偏小

## 3. Mobile-First 信息架构

**移动端（<768px）单屏三段式**：

```
┌─────────────────────────────────┐
│ 头部（极简：品牌 + 登录注册）        │  ← 现有极简头部保留
├─────────────────────────────────┤
│ ① 语言方向条（固定顶部）            │
│    [中文 → English]  ⇄交换  ▼最近  │
├─────────────────────────────────┤
│ ② 对话流（可滚动，占满中间）         │
│    气泡：方向徽标+原文+译文          │
│    + 播放/暂停/重播/复制            │
│    + 顶部「清空本次对话」            │
│    + 预计额度 / 本次额度 轻提示      │
├─────────────────────────────────┤
│ ③ 底部操作区（固定，单手热区）       │
│    ┌─────────────────────┐       │

│    │  点击开始→自动断句      │       │

│    / 翻译中… / 生成语音…           │
└─────────────────────────────────┘
```

**桌面端（≥768px）**：保留现有 A/B 双面板面对面布局，叠加统一升级能力（波形/三段状态/播放控制/额度/最近语言/清空）。

**信息优先级**：录音按钮（主操作）> 方向（当前语境）> 对话流（历史）> 额度（成本透明）> 设置（VAD 灵敏度）。

## 4. 页面状态机

```
                ┌─────────────┐
                │   IDLE      │ ← 初始/每轮结束
                └──────┬──────┘
        点击录音按钮    │
                ┌──────▼──────┐
                │  LISTENING  │ ← 聆听：VAD 自动断句 / 30s 上限 / 波形+计时
                └──────┬──────┘
             VAD 结束 / 超时   │
                ┌──────▼──────┐
                │ PROCESSING  │ ← 三段子状态（SSE 真实推进或节奏动画）
                │  ├ stt       │    「识别中…」
                │  ├ translate │    「翻译中…」
                │  └ tts       │    「生成语音…」
                └──────┬──────┘
            成功 / 降级 / 失败   │
                ┌──────▼──────┐
                │  RESULT     │ ← 气泡入列 + 自动播放（被拦→显式点击播放）
                └──────┬──────┘
          自动回到 IDLE（下一轮）  │
                ┌──────▼──────┐
                │   IDLE      │
                └─────────────┘
```

**子状态细分**：
- `IDLE`：按钮「🎙️ 点按开始（说完自动翻译）」
- `LISTENING`：按钮变红色停止态/不可点（防重复），波形动画 + 「聆听中 Ns · 停顿 1.2s 自动翻译」
- `PROCESSING.stt` → `PROCESSING.translate` → `PROCESSING.tts`：按钮区域显示分段进度文字，全程禁止重复触发
- `RESULT`：短暂（约 0.8s）停留展示新气泡 + 自动播放，然后回 IDLE
- 错误态：从 PROCESSING/IDLE 均可进入 `ERROR`（横幅提示 + 重试按钮），不打断已入列的历史气泡

**方向状态**：`direction = { source, target }` 单一方向（移动端），交换按钮原子翻转；气泡归属由录音时方向决定（A 侧 = 当前方向源语言，交换后为新方向）。

## 5. 交互流程

### 5.1 主流程（点击 → 出结果，全程单手）
```
点击录音 → [权限校验] → LISTENING（波形+计时）→ 停顿1.2s → PROCESSING
→ 气泡入列 → 自动播放译文 → 回 IDLE（可继续说下一句）
```
- 说话时顶部方向条常显当前方向「正在听：中文 → English」
- 30s 强制断句（提示「已到 30 秒上限」）
- 静音 <0.1s → 「没有听到声音，请再说一次」（不调 API 不扣费）

### 5.2 方向交换
顶部 `⇄` 一键交换 source/target（中文→English ⇄ English→中文）；最近使用方向下拉（localStorage 最近 5 个）。

### 5.3 播放控制（每条气泡）
- 默认自动播放（可关，localStorage 已有 `aifanyi_autoplay`）
- 播放中：按钮变「⏸ 暂停」；点击暂停；再点从头播？——**暂停后按钮变「▶ 重播」**（简单明确：暂停 = 停止，重播 = 从头）
- 「复制译文」按钮独立存在
- 自动播放失败 → 气泡内显式提示条「🔇 浏览器禁止自动播放，点击▶播放译文」（**非技术错误文案**）

### 5.4 清空对话
对话流头部「🗑 清空本次对话」→ 轻确认（「清空 N 条？清空/取消」）→ 清空 msgs（仅前端，不影响历史记录落库）。

### 5.5 额度提示（面向用户，不暴露内部概念）
- IDLE：底部操作区常显「预计约 3 额度 / 次」（服务端估算，见 §9）
- 每次结果：气泡区轻提示「本次使用 X 额度」
- 402：横幅「额度不足，请先补充额度」+ 引导（登录/查看额度）
- **绝不出现在界面**：Reserve/Consume/Ledger/available 等词

## 7. 异常状态设计（矩阵）

| # | 场景 | 检测方式 | 用户提示（中文，无技术错误） | 恢复路径 |
|---|---|---|---|---|
| 1 | 首次请求麦克风 | getUserMedia 首次调用 | 浏览器原生权限框（不做覆盖层） | 允许→进入 LISTENING |
| 2 | 用户拒绝（一次性） | NotAllowedError | 「麦克风权限被拒绝，点击重试或到浏览器设置开启」+ [重试] | 重试按钮再次 getUserMedia |
| 3 | 永久拒绝（iOS） | 拒绝后再次请求仍拒 | 「请在 设置→Safari→麦克风 中开启后返回」+ [去设置]（iOS 可跳设置） | 引导设置 |
| 4 | 无麦克风设备 | NotFoundError | 「未检测到麦克风设备」 | 检查设备后重试 |
| 5 | 开始录音 | 成功 | 波形 + 「聆听中 Ns」 | — |
| 6 | 自动断句 | VAD 静音 1.2s | 自动进入处理（气泡前短暂过渡动画） | — |
| 7 | 语音过短（<0.1s 采样） | 前端采样数 | 「没有听到声音，请再说一次」（不调 API 不扣费） | 回 IDLE |
| 8 | 无声音（ASR 空） | 后端 502「没有听清」 | 同 7 文案 | 回 IDLE |
| 9 | 长时间说话 | 30s 计时 | 自动断句 + 气泡标注「已到 30 秒上限」 | 正常出结果 |
| 10 | STT 失败 | 后端 502 stt 段 | 「识别失败，请靠近麦克风再说一次」+ [重试] | 重试（不扣费，已退回） |
| 11 | 翻译失败 | 后端 502 translate 段 | 「翻译服务暂时不可用，请稍后重试」+ [重试] | 重试 |
| 12 | TTS 失败 | ttsFailed=true（降级） | 气泡正常出译文 + 「语音生成失败，可复制译文」 | 不阻塞，文字可用 |
| 13 | 自动播放被浏览器阻止 | Audio.play() reject | 气泡内「🔇 已停止自动播放，点击▶播放」 | 显式点击播放 |
| 14 | 切后台 | visibilitychange hidden | 录音中→自动取消 + 提示「录音已取消」；处理中→请求继续，回前台显示结果 | 回前台正常 |
| 15 | 锁屏 | visibilitychange + AudioContext suspended | 同 14；若处理中，锁屏中断请求→按网络异常处理 | 回前台重试 |
| 16 | 来电 | AudioContext statechange 'suspended' | 录音自动取消，提示「录音已取消」 | 挂断后重试 |
| 17 | 网络中断 | navigator.onLine false / fetch 失败 | 「网络异常，请检查网络后重试」+ [重试] | 恢复后重试 |
| 18 | Credit 不足 | 后端 402 | 「额度不足，请先补充额度」+ [查看额度]（引导登录/额度页） | 补充后重试 |
| 19 | 操作太频繁 | 后端 429 | 「操作太频繁，请稍等片刻」 | 自动倒计时后恢复 |
| 20 | 重复点击 | 状态机防抖（LISTENING/PROCESSING 中按钮不可触发） | 按钮态变化本身即是反馈 | — |
| 21 | 快速连续两句话 | 每轮独立 + 单例互斥；VAD 结束自动进下一轮 | 第一句处理中按钮置灰 | 结果后自动恢复 |

**通用原则**：所有错误文案用户可读、可操作（带重试/引导按钮）；失败不打断历史气泡；金额相关只用「额度」一词。

## 8. iOS / Android 兼容方案

| 主题 | iOS Safari | Android Chrome | 处理 |
|---|---|---|---|
| 麦克风权限 | 首次弹窗；**拒绝后再次请求直接拒（需去设置）** | 可多次请求；地址栏可改 | 区分一次性/永久拒绝文案（§7 2/3）；Android 重试按钮直接再 getUserMedia |

| 字体 | <16px 输入框触发页面缩放 | 同 | 页面无 <16px 输入框（已有） |

## 9. 技术方案（最小后端改动，优先兼容）

### 9.1 三段处理状态：推荐「SSE 事件流」（真实进度）
- 后端 `/api/voice/translate` 增加可选 `?stream=1`：响应改 `text/event-stream`，依次推送：
  `{stage:'stt'}` → `{stage:'translate'}` → `{stage:'tts'}` → `{done:true, text, translation, audioBase64, ttsFailed, usedCredits}`
- **非流式调用完全不变**（TranslatorBox/VoiceTranslateButton/现有 E2E 继续用原响应）
- 前端 `fetch + ReadableStream` 解析 SSE，驱动三段子状态
- 结算逻辑零改动（三段 beginSync/endSync 原样保留，仅在段间插入 event push）
- **备选（零后端改动）**：前端固定节奏动画「识别中→翻译中→生成语音」+ 真实总时长均摊——进度是模拟的，不推荐但可行

### 9.2 「本次使用 X 额度」
- 后端 translate 响应（流式 done 事件 + 非流式响应体）统一追加 `usedCredits`（三段实际 consume 之和；TTS 降级失败段不计）
- 前端仅展示数字

### 9.3 「预计约 X 额度」
- 扩展 `/api/credit/estimate` 支持 `feature=voice&seconds=15`（STT 分钟价 + 翻译千字价 + TTS 千字价 估算，服务端算价）
- 前端录音开始前查询一次，LISTENING 中按已录秒数实时更新（可选）

### 9.4 最近使用语言
- localStorage `aifanyi_recent_langs`（最近 5 个 `source:target`），方向条下拉选择

### 9.5 组件拆分（可维护性）
```
src/lib/voice/useVoiceSession.ts     ← 核心状态机 hook（录音/VAD/调用/播放/异常，UI 无关）
src/components/voice/VoiceMobileView.tsx   ← 移动端布局（<768px）
src/components/voice/VoiceDesktopView.tsx  ← 桌面端布局（≥768px，双面板）
src/app/voice/page.tsx               ← 入口（极简头部 CSS 保留）
```
- 断点用 `window.matchMedia('(max-width: 767px)')`（避免 CSS 媒体查询与 React 状态不同步）
- 桌面端复用同一 hook，保留 A/B 双会话实例（useVoiceSession 支持 side 参数）

### 9.6 明确不动的东西
- `/api/voice/{transcribe,tts,translate}` 既有请求/响应结构（仅新增字段与可选 stream）
- 认证（session/登录/Google OAuth）、Credit Engine（reserve/consume/ledger）、定价表
- 录音不落库承诺（原始音频仅内存 → API → 丢弃，维持「录音仅用于本次翻译，不会保存」）
- 首页翻译框、导航、页脚

## 10. 验收矩阵（5 设备 × 关键场景）
