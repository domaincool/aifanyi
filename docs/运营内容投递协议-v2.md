# 运营内容投递协议 v2（aifanyi.com）

> 版本：v2（2026-08-15）｜适用：运营 Agent（agent-p6qd）→ 内容系统
> v2 变更：**Primary 通道 = 后台直录 API；handoff 降级为 Fallback 兜底**。后台数据为准。

## 一、通道主次（已拍板）

| 通道 | 角色 | 适用场景 |
|---|---|---|
| **后台直录 API** | **Primary** | 正常日常投递（词条/盲测题），运营直接写入，保存即生效 |
| **handoff 文件** | **Fallback** | 接口异常、校验失败、需人工确认、token 失效时的兜底 |

原则：
- 正常情况**优先直接写后台**，不再依赖 handoff 完成日常投递
- handoff 不是与后台平级的第二套数据源，**最终以后台数据为准**
- 两个通道共享同一查重/幂等逻辑，不会重复入库
- 目标：后台稳定后逐步降低 handoff 使用频率，保留作安全保险

## 二、Primary 通道：后台直录 API

### 2.1 认证
- 请求头：`Authorization: Bearer <OPS_API_TOKEN>`
- Token 由工程师下发（存服务器 .env，不入 git）；失效/轮换时工程师通知

### 2.2 词条批量导入（主端点）

```
POST https://aifanyi.com/api/admin/memes/import
Authorization: Bearer <OPS_API_TOKEN>
Content-Type: application/json
```

请求体：

```json
{
  "batchId": "meme-batch-008-20260815",
  "dryRun": true,
  "updateExisting": false,
  "items": [
    {
      "term": "绝绝子",
      "slug": "jue-jue-zi",
      "meaning": "形容好到极致",
      "translation": "Absolutely amazing / Top-notch",
      "example": "这家店的服务绝绝子！",
      "tags": ["流行", "感叹"],
      "popularity": 95,
      "category": "流行语"
    }
  ]
}
```

响应（dryRun=false）：

```json
{
  "ok": true,
  "batchId": "meme-batch-008-20260815",
  "imported": 45,
  "updated": 0,
  "skipped": 3,
  "conflicts": [{ "index": 4, "term": "绝绝子", "reason": "term_exists" }],
  "created": ["jue-jue-zi"]
}
```

### 2.3 标准流程（运营侧）

1. 整理 JSON（字段同现有 meme-batch-XXX.ts，term/slug/meaning/translation/example/tags/popularity/category）
2. 先 `dryRun: true` 预览 → 看 `conflicts`（term 重复 / slug 冲突 / 字段缺失）
3. 修正可自动修的行；无法判定的跳过并记录
4. `dryRun: false` 正式导入
5. 会话回执：「收到，已导入 N 条（skipped M）」→ 完成

### 2.4 其他端点

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | /api/admin/memes | 单条创建 |
| PATCH | /api/admin/memes/[id] | 编辑 / 上下架（status: draft/published/archived） |
| GET | /api/admin/memes | 列表/搜索/验证 |
| POST | /api/admin/blindtests/import | 盲测题批量（Phase C 接线，译文异步生成） |

### 2.5 幂等与去重（双通道防重核心）

- **batchId 幂等**：同一 batchId 重复提交返回首次结果，不重复入库
- **term 唯一**：已存在 → skipped（updateExisting=true 则更新）
- **slug 双风格查重**：`yueguangzu` 与 `yue-guang-zu` 视为冲突（沿用既有库经验）
- **handoff 兜底数据同样走本接口入库** → 永远只有一套查重逻辑

## 三、Fallback 通道：handoff 文件

### 3.1 触发条件（任一命中即回退）

| 条件 | 说明 |
|---|---|
| 5xx / 超时 | 自动重试 3 次（指数退避）仍失败 |
| 401/403 | token 失效，停止调用，会话通知工程师换 token |
| 校验失败无法自动修正 | 附错误明细 |
| 冲突率 > 20% | 可能数据版本错乱，需人工核对 |
| 需人工确认 | 疑似历史数据被误改等 |

### 3.2 文件格式（沿用命名 + 新增状态节）

```
文件名：meme-batch-<序号>-<YYYYMMDD>.md（如 meme-batch-008-20260815.md）

## 处理状态: PENDING
## 回退原因: 接口 5xx 重试 3 次失败
（数据 JSON 数组放正文代码块）

## 处理状态: IMPORTED（imported 45 / skipped 3 / conflicts: 绝绝子 term_exists）
（工程师处理完后写回）
```

### 3.3 流程

1. 运营写文件（PENDING + 回退原因）→ 会话短通知
2. 工程师读取 → 提取数据 → 调**同一个** /api/admin/memes/import（不直接写库）
3. 结果写回状态节 → 会话回执 → 运营归档

## 四、协作确认标记（沿用）

- 双方回复带「收到 xxx」确认标记，避免投递延迟导致重复处理
- 运营侧按回执内容核验线上（词条页 200 / sitemap 数量）

## 五、过渡期说明

- Phase B 上线初期：handoff 照常可用，双通道并行观察
- 后台稳定（连续 N 批直录无回退）后：日常投递全部走 Primary，handoff 仅作保险
- 变更通知：本协议任何调整由工程师发版更新并会话告知
