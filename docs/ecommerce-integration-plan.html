三、Storage Architecture

StorageService 接口
interface StorageService { upload(file, meta): Promise<{storageKey, url}> get(storageKey): Promise<Buffer|Stream> delete(storageKey): Promise<void> getSignedUrl(storageKey, ttlSeconds): Promise<string> }
环境实现
DevelopmentLocalStorageService：磁盘 <root>/storage/<uuid>
ProductionS3CompatibleStorageService：R2 / S3 / OSS（S3 API 兼容）
访问鉴权（Signed URL）：① 前端请求文件 → 后端校验 userId + Project 归属 → ② 生成短期 Signed URL（15 分钟 TTL）→ ③ 浏览器直连 Storage → ④ 不公开永久 URL，bucket 不设公开读
生命周期（soft delete → async cleanup）：① 删除 Product/Asset → DB status=deleted → ② 异步 cleanup job（cron）扫软删记录 → 删 Storage 文件 → 硬删 DB → ③ 用户请求内不同步删大量文件

四、Credit Architecture

  • 配置化：定价存 PricingRule 表（seed upsert），代码只读表，不硬编码单价。
  • 前端展示：只显示「预计使用 X 额度」「本次使用 X 额度」，不显示 token / 模型成本 / 内部账本。
  • Listing Generation UX：以「任务预估额度」呈现，不暴露「每 1000 字符多少钱」。
  • Reserve 阶段拦截：提交前 estimate → reserve 原子检查（行锁）→ 不足 402 → 前端弹「本次预计需要 XX Credits / 当前可用 XX Credits」+ [获取额度][取消] → 绝不先执行再扣费。

五、Product UX（Product-first）

用户进入工作台 /ecommerce 直接看到「我的商品」→ 创建商品（Quick：名称+描述 → AI 提取补全；Advanced：SKU/Brand/Materials/Dimensions/Weight/Specifications）→ 商品工作区 → Listing / Images / Messages Tab

Project 仅作 DB 归属字段 + 未来组织能力，默认自动归属「默认项目」，不暴露给普通用户。

七、Acceptance Criteria（场景 1–8）

  1. 登录 → 建商品（Quick）→ AI 提取补全 → Amazon US → 一次生成完整 Draft（5 块齐全）→ 逐字段编辑 → 保存 → Copy/TXT/CSV·JSON 导出 → 扣费正确
  2. 上传图片 → OCR → 翻译 → 布局重建预览（「尽可能保持原始布局和视觉结构」）→ 下载（Signed URL）
  3. 英文客户消息 → 中文翻译 → 意图 → AI 回复 → 改语气 → 复制
  4. 额度不足 UX：Reserve 拦截，显示「本次预计 XX / 当前可用 XX」+ [获取额度][取消]，不先执行不扣费
  5. Provider 失败 → FAILED → Reserve 自动 Refund → 友好提示
  6. 重复点击 → 不重复建任务、不重复扣费（幂等）
  7. 用户 A 不能访问用户 B 的 Product/Asset/Message（IDOR 全拦）
  8. 文件走短期 Signed URL，无永久公开 URL；删除走 soft delete → cleanup
