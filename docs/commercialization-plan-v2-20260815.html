〇、核心结论：aifanyi 到底靠什么赚钱

一句话回答：aifanyi 不靠「翻译」赚钱，靠「跨境电商工作台的订阅」赚钱；翻译是获客引擎，Credits 是计费底座，Pro 是稳定现金流。

价值层角色变现逻辑判断
免费翻译（文本/工具）流量引擎几乎零成本（DeepSeek 极廉 + GLM-4-Flash 免费档），靠量获客不直接赚钱，也不该指望它赚钱
Credits 统一计费计费底座把「用多少算多少」标准化，是后续一切付费的底层是「管道」不是「商品」

跨境电商工作台ARPU 提升引擎卖家刚需、高频、可量化 ROI，客单价最高真正利润来源
Pro / Business 订阅长期订阅收入引擎额度 + 高级功能 + 更低单位成本，锁客稳定经常性收入
对 V1 的批判性修正：V1 把「1 Credit = ¥0.10」当作既定锚点直接推导，这是错的。统一汇率掩盖了成本结构的巨大差异——文本翻译毛利 >100 倍，而 ASR（¥0.06/分）在 ¥0.10/分 锚点下毛利仅 40%，叠加手续费/退款/滥用可能亏损。V2 改为「分功能差异化定价 + 锚点仅作参考」。

核心判断：普通翻译用户与跨境电商用户必须采用不同商业模式

为什么：普通翻译用户是「低频、低客单、价格敏感、无 ROI 概念」的长尾；跨境电商用户是「高频、高价值、愿为效率付高价、能量化 ROI（listing 质量直接换销量）」的核心人群。把两者塞进同一个订阅，要么拉低客单价，要么吓退普通用户。

重点研究结论

  • PDF 是否适合做 Free→Pro 转化器？——适合，强烈推荐。文档翻译是「工作刚需」，用户愿为「上传即译、双语对照、可下载」付费；且 PDF 分页计费天然制造「额度不够→充值/升级」的触发点。策略：PDF 保留在免费额度内可用（获客），但额度耗尽后引导升级 Pro（而非纯充值），因为 Pro 含「更高 PDF 页数上限 + 更低单价」。
  • 跨境电商工作台是否该做高客单产品？——是，独立成 E-commerce Pro。卖家为 ROI 付费，客单价可到 ¥99-199/月，是 aifanyi 的利润引擎。见第七章。

为什么这样定价（不是只给数字）

  • 首付门槛 ¥6 是「付费意愿探测器」，转化率比 ¥30 高，但绝对收入低——它的价值是「让用户完成第一次支付」，不是赚钱。
  • 主力 ¥30 是「利润档」，靠赠送梯度（10%）制造划算感，是大多数用户最终选择的档位。
  • 重度 ¥98 面向跨境卖家，20% 赠送拉低单位成本到 ¥0.083，暗示「重度用户该上订阅了」。
  • 第一阶段故意不做 ¥298 以上大包、不做订阅——先验证「有没有人愿意为翻译/工具付费」，再为确定需求上复杂体系。

预计毛利：文本类 95%+，ASR/TTS 若走点数包会拉低整体毛利，故第一阶段点数包主要覆盖文本/PDF/文档，语音功能在 Pro 上线前暂以额度内按 1 cr 计费。

9.2 三个「何时」

  • 何时提示购买：余额不足以覆盖本次预估消耗时（而非余额归零时），让用户在「知道自己还要用」的当下做决定。
  • 何时推荐订阅：检测到「30 天内消耗 > X 额度」或「使用 PDF/文档/跨境功能」的高频用户，推送 Pro/E-com Pro，因为订阅的单位成本更低、更划算。
  • 何时不打断：游客首次体验、免费额度充足、正在语音实时翻译中等场景不弹付费，保护体验。
发现现有 UX 断点：CreditClient 文案写「额度用完后按用量计费，用量透明可查」——但当前没有任何充值入口，这是「死胡同」承诺。V2 首要修复：把这句话改成可执行的「额度不足→购买/升级」动作，而不是一句无法兑现的承诺。

十、支付方案（先定市场与主体，再选渠道）

V1 批判：V1 给了「先 MoR 再个体户」的路线，但未先厘清「目标市场 + 收款主体」。支付渠道必须由这两者决定，不能反过来。

决策推荐理由

收款主体个体户（可代办，几百元）接入微信/支付宝必须企业或个体户主体；个体户成本最低、可开票

10.2 渠道选型（市场+主体确定后）

渠道适用费率备注

10.3 支付技术要点（沿用现有安全原则）

  • Webhook 回调 + 幂等键防重复充值；订单状态与支付状态分离；到账以「我方 grant 成功」为准。
  • Refund：未消费余额原路退（Refund 流程已备）；已消费不退。
  • 对账：复用「available + reserved == ΣLedger.amount」与支付流水日对账。
  • 税务/发票：个体户主体可开电子发票；海外 MoR 由平台代开收据。
  • 支付密钥不入 git、不落业务库。

十四、明确「现在不要做什么」

可开发但暂不做原因
复杂会员等级（铜银金钻）用户基数 19 人，等级体系空转
过多 SKU（4 档以上点数包 + 多档订阅）商城复杂化，分散决策，增加客服成本
Affiliate / Referral 分销无流量规模时无意义，且有刷量风险
企业合同系统 / 线下对公Business 阶段的事
API 商业化需独立计费/限流/文档体系，过早投入
复杂优惠券 / 满减 / 积分商城过度设计，先跑通基础付费
多地区支付 / 多币种先国内单币种，海外是补充不是主战场
一句话：不要为了「完整」而过度设计。当前阶段只做「让第一个用户能付钱，且付得舒服」这一件事。

十五、最终老板拍板事项（10 项）

1. Credit 价格锚点
推荐：文本类 ¥0.10/千字锚、图片 ¥0.30/张、ASR/TTS 抽离为 Pro 权益不单点计费
备选：统一 ¥0.10 汇率（简单但 ASR 毛利 40% 有亏损风险）
理由：分功能差异化匹配真实成本结构
不决定影响：后续所有 SKU 定价与毛利测算无法落地
2. 第一阶段充值 SKU
推荐：¥6/¥30/¥98 三档
备选：只上 ¥30 单档（更快但缺首付门槛与高 ARPU 档）
理由：首付门槛 + 锚点 + 高客单三档各司其职
不决定影响：P1 无法排期开发
3. Pro 是否上线
推荐：现在不建订阅，P1 先点数包，P2 再灰度 Pro
备选：P1 直接上 Pro
理由：先有付费数据再建复杂会员
不决定影响：若强行上订阅，可能做了没人买的会员体系
4. E-commerce Pro 定位
推荐：方案 B 独立订阅层（¥99-199 候选）
备选：C（Pro + Add-on）
理由：利润引擎需独立定价，不拖累 Pro
不决定影响：跨境工作台商业化无方向
5. Free 额度
推荐：保留 300 赠送 + 30 天有效期，打「新人礼」标签
备选：下调到 100
理由：300 足够体验完核心功能，30 天制造转化紧迫感
不决定影响：获客转化与防滥用平衡难定
6. Credits 有效期
推荐：充值额度永久/长有效，赠送额度 30 天
备选：全部永久
理由：充值是真金白银应保值，赠送可过期制造转化
不决定影响：用户协议与过期逻辑口径不清
7. 支付市场
推荐：先国内 RMB
备选：同时海内外
理由：核心付费人群在国内，先单币种跑通
不决定影响：收款主体与渠道无法选定
8. 收款主体
推荐：个体户（可代办）
备选：海外 MoR（Lemon Squeezy）
理由：微信/支付宝必须主体，个体户成本最低
不决定影响：支付无法接入
9. PDF 收费策略
推荐：PDF 作 Free→Pro 转化器，额度内免费、超额引导升级 Pro
备选：PDF 直接点数收费
理由：文档场景付费意愿高，适合做订阅转化触点
不决定影响：付费转化引擎缺失最强抓手
10. Business 是否进入下一阶段
推荐：暂缓，Phase 4 再做
备选：提前规划
理由：团队/API/协作是规模化后的事
不决定影响：无（暂缓不影响当前）
